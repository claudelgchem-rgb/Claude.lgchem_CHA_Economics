# DESIGN_PRINCIPLES.md

경제성 분석 플랫폼(Cost / Economics Analysis Platform) UI 리디자인의 미적 기준 문서.
모든 에이전트는 이 문서를 **단일 진실 공급원(single source of truth)** 으로 삼는다.
이 문서를 위반하는 산출물은 design-director / visual-critic 가 **스스로 거부(reject)** 한다.

---

## 0. 대전제

- **로직 불변(Logic Immutability)**: 이 문서는 *프레젠테이션 레이어*에만 적용된다.
  이벤트 핸들러·상태 관리·데이터 흐름·계산식·API/DB 호출·비즈니스 규칙·콜백·라우팅·폼 제출
  로직은 한 글자도 바꾸지 않는다. (경계 정의는 `EDIT_BOUNDARY.md`)
- **고급스러움 = 절제(Restraint)**: 화려함이 아니라 **타이포그래피 위계 · 여백 규율 ·
  정렬 디테일**로 "있어 보이게" 만든다.
- **도구의 정체성**: 이것은 마케팅 랜딩 페이지가 아니라 **숫자를 다루는 분석 도구**다.
  화면의 주인공은 데이터이지 장식이 아니다.

---

## 1. 회피할 "AI 티" 클리셰 (BANNED)

아래는 *의도적으로 회피*한다. 하나라도 발견되면 visual-critic 는 FAIL 처리한다.

1. **보라/인디고 → 핑크 그라데이션** (버튼·히어로·텍스트·아이콘 어디에도 금지)
2. **글래스모피즘 남용** — 반투명 블러 카드(`backdrop-filter: blur`)를 기본 카드 스타일로 깔지 않는다
3. **pill 일색** — 모든 모서리를 과하게 둥글린 알약형(완전 라운드) 버튼/배지 도배
4. **어두운 배경 + 네온/고채도 액센트** (사이버펑크 대시보드 룩)
5. **이모지를 아이콘·헤딩에 사용** (🚀 ✨ 💡 📊 🔥 등) — 절대 금지
6. **가운데 정렬 랜딩형 히어로** + 뒤에서 빛나는 그라데이션 blob/orb
7. **모든 요소에 동일하게 깔린 부드러운 드롭섀도** (균질한 `box-shadow` 남발)
8. **기본 Tailwind/shadcn/Bootstrap 룩을 손 안 댄 채 방치** (디폴트 컴포넌트 그대로 노출)
9. **그라데이션 텍스트로 "프리미엄" 흉내** (`background-clip: text` 그라데이션 헤딩)
10. **과도한 라운드 + 과도한 패딩 + 과도한 섀도** 3종 세트로 모든 카드를 "풍선"처럼 만들기
11. **중앙 정렬된 긴 본문** (가독성 저해) 및 무의미한 풀스크린 여백 낭비
12. **의미 없는 장식 아이콘** — 모든 라벨 옆에 동그란 컬러 아이콘 배지 붙이기

## 2. 추구할 방향 (PREMIUM / EDITORIAL RESTRAINT)

### 2.1 팔레트 — 절제된 의도
- **차분한 뉴트럴 베이스**(웜/쿨 그레이, 오프화이트)를 바탕으로 한다.
- **액센트는 1~2개**만. 딥 잉크(deep ink), 웜 그레이, 절제된 단일 브랜드 컬러 정도.
- 고채도/네온은 쓰지 않는다. 색은 *강조*가 아니라 *질서*를 위해 쓴다.
- 배경은 순백(#FFFFFF)보다 살짝 가라앉은 오프화이트, 텍스트는 순흑(#000)보다 잉크 톤.

### 2.2 타이포그래피 — 강한 위계
- **명확한 위계**: Display / H1 / H2 / H3 / Body / Caption / Mono(숫자) 역할을 분리한다.
- 헤딩은 개성 있는 산세리프 또는 절제된 세리프. 본문은 편안한 가독성 우선.
- 위계는 *크기*뿐 아니라 **굵기·자간·색·여백**의 조합으로 만든다.
- 한 화면에 서체는 최대 2종(+모노). 무분별한 폰트 혼용 금지.

### 2.3 숫자 표현 규칙 (경제성 분석 도구의 핵심)
- **Tabular lining figures** 사용 (`font-variant-numeric: tabular-nums`) — 자릿수 정렬.
- 숫자는 **우측 정렬**, 단위/라벨은 좌측 또는 보조 위계.
- **소수 자릿수 일관성** — 같은 컬럼/지표는 항상 동일한 자릿수.
- **천 단위 구분자** 사용. 큰 수는 단위(억/만/K/M)로 축약하되 일관 규칙 유지.
- **단위는 보조 위계**로 — 숫자보다 작고 옅게. 숫자가 주인공.
- **양/음수 구분은 절제** — 네온 적/녹 금지. 음수는 부드러운 레드-잉크 또는 괄호/마이너스,
  양수는 기본 잉크색. 색에만 의존하지 말고 기호/부호도 함께 쓴다(접근성).

### 2.4 여백 & 그리드
- **정의된 스페이싱 스케일**(4 / 8px 베이스: 4, 8, 12, 16, 24, 32, 48, 64)만 사용.
- 넉넉하고 **일관된** 여백. 의도된 화이트스페이스로 그룹을 구분한다.
- 실제 **그리드**와 **광학적 정렬(optical alignment)** 규율을 지킨다.
- 밀도와 가독성 양립: 데이터는 빽빽해도 *정렬*되어 있으면 고급스럽다.

### 2.5 경계 & 엘리베이션
- **헤어라인 보더(1px, 저대비)** 우선. 무거운 섀도는 지양.
- 엘리베이션이 필요하면 **조용하게** — 아주 옅은 단일 섀도 한 단계.
- 카드 구분은 보더/배경 톤 차이로. 풍선 같은 둥근+섀도 카드 금지.

### 2.6 표 (Tables) — 데이터의 집
- **헤어라인 행 구분선** + **넉넉한 셀 패딩** + **고정 헤더(sticky)**.
- 숫자 컬럼 우측 정렬, 텍스트 컬럼 좌측 정렬.
- 헤더는 약한 대비로 위계 표현(굵기/색/대문자 자간). 형광펜식 배경 금지.
- zebra-striping 보다 헤어라인 + 호버 하이라이트를 우선.

### 2.7 인터랙션 & 모션
- **조용한 상태(state)**: hover/focus/active 는 미묘한 톤 변화와 또렷한 포커스 링으로.
- 모션은 **절제** — 빠르고 짧은 이징(150–200ms), 과한 바운스/페이드 금지.
- 포커스 가시성은 접근성을 위해 항상 명확히 유지.

### 2.8 접근성
- **대비(WCAG AA 이상)** 준수. 텍스트/배경, 액센트/배경 대비를 검증한다.
- 색만으로 정보를 전달하지 않는다(부호·아이콘·라벨 병행).
- 키보드 포커스 순서와 가시성 유지.

## 3. 레퍼런스 감각 (지향점)

- **Stripe Dashboard** — 헤어라인, 절제된 색, 숫자 가독성
- **Linear** — 위계·여백·조용한 인터랙션
- **Mercury / Ramp** — 금융 데이터의 신뢰감 있는 표현
- **FT / The Economist 데이터 비주얼** — 에디토리얼한 차트·타이포
- **고급 컨설팅 리포트(맥킨지/BCG 덱)** — 절제된 그리드와 숫자 위계
